# 433｜資產再配置版本入口

以實際持倉、本次目標與交易限制，產生可核對的臺股 ETF 再平衡方案。歷史專案名稱保留為 433，**不預設 40／30／30、4312 或其他固定權重**。

## 網頁版本

正式入口：https://tanaka-z2000.github.io/433/

原始版 V1：https://tanaka-z2000.github.io/433/versions/v1/

日常操作版 V2：https://tanaka-z2000.github.io/433/versions/v2/

V2 暫用模式：https://tanaka-z2000.github.io/433/versions/v2/?mode=temporary

首頁只提供版本選擇，不讀寫持倉資料。V1 保留原有五個區塊、計算與保存方式，並提供返回入口的連結。V1 沿用 `433.portfolio.v1`，在相同瀏覽器、相同網址來源下，入口建立前的持倉與快照仍可讀取。不同路徑本身不會隔離 localStorage，因此每個新版本必須使用不同保存鍵。

版本清單由 `versions.json` 管理。每一版本使用獨立的 `versions/<id>/index.html`、`src/` 與測試目錄。Vite 一次建置入口與所有已登記版本；沒有客戶端路由，直接開啟版本網址或重新整理也能使用。

新增版本範例：

```sh
npm run version:new -- v2 v1
```

此指令複製 V1 為獨立 V2，建立新的資料保存鍵，並登記為試用版。若版本已存在則停止，不覆蓋。後續只修改 `versions/v2/`，再更新 `versions.json` 的名稱、功能差異與狀態。完成測試後部署，入口才會出現可實際使用的新選項。不要為了新功能修改 V1；保留的來源內容可透過 Git 比對。

各版本目前共用鎖定的套件與建置工具。更新共用依賴時需對所有版本執行測試；個別介面、計算與保存程式不共用，避免新版功能更動影響舊版。

## 原始版使用方式

1. 填現金餘額與 T+2 交割款：正數應收、負數應付。交割款指尚未反映於現金餘額的金額；完成交割後更新餘額並清除對應款項，避免重複計算。
2. 新增實際持倉、股數與試算價格。自行確認哪些標的是「台股正二」，監測清單不代表持倉。
3. 所有目標留白時只檢查現況；需要調整時，完整填寫各標的與現金目標，合計須為 100%。現金下限至少 10%，可以提高；現金目標可高於下限。
4. 比較完整再平衡、僅用新增資金、容許區間調整。交易限制可選允許買賣、不能賣但可買、完全不動。
5. 檢查股數、費用、剩餘現金與偏差，匯出方案。工具不連接券商、不下單。
6. 「套用估計方案供核對」會先保存原始快照，更新估計股數及交割款，並把投入／提領歸零。實際成交後須自行核對成交價格、股數與現金差額；此操作不是成交紀錄或成交確認。

首次開啟不帶入推定持倉。示範資料明確標示且需要確認載入。

## 計算口徑

- 目前總資產 = 各標的股數 × 試算價格 + 現金 + 有正負號的交割款。
- 本次資產基準 = 目前總資產 + 投入／提領（正投負提）。
- 調後總資產 = 本次資產基準 − 預估交易成本。
- 現金比率 = 調後淨現金 ÷ 調後總資產。這是 **T+2 交割後淨額**，不是盤中可下單額度；工具不模擬各日券商交割時序。
- 費率選項：未折扣手續費 0.1425%（買賣皆收），最低手續費預設 0 元；證交稅僅賣出收取，一般股票 0.3%、股票型 ETF（含 00662、台股正二）0.1%。新增標的預設一般股票；ETF 可一鍵套用對應費率。既有保存／匯入的自訂費率保留，亦可透過按鈕重設。未套用股票當沖優惠或其他商品減免。
- 費用每標的視為一筆委託：`max(最低手續費, 成交金額 × 手續費率) + 賣出金額 × 交易稅率`，估計至分。請按商品與券商修改費率、最低費用與交易單位；實際券商進位、折扣與分筆成交可能不同。
- 1 股表示零股、1000 股表示整張。剩餘零股不會因整張設定被強制出售。
- 完整模式先賣超額，再按目標金額缺口由大到小買入，保留以費用前資產計算的現金目標，因此費用後通常有少量保守緩衝。
- 僅投入模式不賣出，買進加費用不超過本次正投入；既有現金不足下限時優先保留現金。
- 區間模式只調整超出容許偏差者，向區間邊界靠攏。這是可解釋的啟發式方法，**不保證全域最少交易、最佳化解或每個可行目標均能達成**。
- 未達現金下限、未持有 00662／台股正二、未達目標時會列出缺口，不宣稱配置已完成。限制衝突不會偷偷解除鎖定。

## 保存與備份

持倉與最多 50 份快照保存在此網站來源的 localStorage；不上傳持倉。來源、網域或瀏覽器改變時不會自動同步，清除瀏覽器資料也會清除紀錄。請定期匯出 JSON 備份。

只有完整且通過驗證的輸入會自動保存。編輯中缺欄、錯誤目標等暫存狀態不會覆蓋上次有效資料。舊版沒有持久化資料，沒有自動匯入舊頁狀態。

- JSON 包含全部設定與快照；匯入需先確認覆蓋。市場觀察筆記區塊已移除；舊版備份中的筆記仍保留於備份資料，不在介面呈現，以維持相容性並避免意外遺失舊資料。
- CSV 只匯入／匯出持倉，欄位順序見匯出的空白範本；現金與交割款不受 CSV 覆蓋。代號使用文字，請留意試算表不要移除前導零。
- 來源網址只允許 HTTP(S)。CSV 匯出會防止文字欄位被視為試算表公式。
- 讀到損壞或未知版本的本機資料時，停止自動覆蓋並提供原始資料下載。
- 快照資產差額包含現金流與行情變化，不能稱為投資報酬。

## 情境試算

情境試算採各 ETF 自身的假設漲跌幅，基於目前持倉、不含本次投入／交易／成本；不把多日指數報酬乘二當作正二長期報酬。

目前沒有串接即時行情、排程晨晚報或券商。

## 開發與驗證

Node.js 24（與 CI 一致）：

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
npm run format:check
```

所有依賴以 package-lock.json 鎖定，正式頁面不載入 CDN React、Tailwind 或 Babel。

- `versions/v1/src/engine.ts`：純計算函式、驗證、交易費用與方案。
- `versions/v1/src/storage.ts`：版本化備份、CSV 與檔案下載。
- `versions/v1/src/main.tsx`：繁體中文響應式介面。
- `versions/v1/tests/engine.test.ts`：資金守恆、限制、取整、費用、輸入與可攜資料測試。
- `tests/browser_smoke.py`：選用 Chromium 操作驗證（Python Playwright）。先建置並在 8001 埠啟動 `python3 -m http.server 8001 --directory dist`，再執行 `python3 tests/browser_smoke.py`。可透過 `PORTFOLIO_URL`、`CHROMIUM_PATH` 指定網址與瀏覽器。

## GitHub Pages

`tests/portal_smoke.py` 驗證入口連結、原始版返回入口、既有資料延續及手機排版。

PR 自動執行所有版本的測試、型別檢查與建置。合併到 main 後，Pages workflow 建置 `dist` 再部署；首次需在儲存庫 Settings → Pages 選擇 GitHub Actions。也可手動觸發 Pages workflow。

部署後會核對正式入口及 V1 五個區塊。Vite 使用相對資源路徑，支援 `/433/` 與 `/433/versions/v1/` 子目錄。不要直接發布原始碼根目錄作靜態頁面；應發布 `dist`。舊副本已移除，可由 Git 歷史取回。

## V2 日常操作版 2.0.0

V2 以試用版並存，保留 V1 的來源檔與資料保存鍵。五個主區塊維持不變；V2 使用 `433.portfolio.v2`，只有手動匯入才會搬移資料。沒有後端、帳號登入或雲端持倉同步。

### 保存與備份

- 連續輸入暫停 650 毫秒後保存，內容相同不重複寫入；頁面隱藏或離開時嘗試補存有效內容。行動裝置強制結束瀏覽器不保證觸發離頁事件，請確認已保存再離開。
- 顯示保存成功、修改未存、失敗、資料文字大小估算與快照數量。容量估算是 UTF-16 文字大小，並非實際磁碟配置或瀏覽器剩餘額度。
- 另一個分頁變更或清除 V2 資料時停止保存，避免直接覆蓋。使用者可先匯出後重新載入，或明確確認以目前內容重新啟用保存。
- 最近匯出時間與 SHA-256 內容摘要隨備份保存；用於提示內容是否已變更，不代表檔案成功落地、加密或防竄改認證。匯出使用瀏覽器下載，需自行確認完成。
- 匯入前預覽來源、標的數、現金、交割款、快照數及核對狀態。V1 JSON 可匯入 V2；V2 格式不回寫 V1。CSV 只取代持倉，保留現金、快照及核對狀態。檔案上限 8 MB。
- 45 份快照起提醒整理，50 份時停止新增與套用方案，不自動淘汰舊紀錄。刪除需確認。
- `?mode=temporary` 在初始化之前決定暫用模式，不讀取或寫入 localStorage；重新整理或離開會失去未匯出的內容。這不是防側錄或惡意程式的安全隔離。

### 日常操作與核對

- 目標合計與不足／超出比例直接顯示；快速價格輸入區及每標的費率摘要讓日常更新較簡單。價格時間是輸入時間，不是行情報價時間。
- 三種模式並列買賣金額、交易費用、現金與最大目標偏差；交易列附上計算依據。延續 V1 計算原則與費率，沒有增加最適化承諾。
- 保存試算方案會保留原始價格、費率、模式及預估結果，不改動目前持倉。
- 套用估計方案先保留原始快照，再持久保存「待成交核對」狀態；編輯和重新整理不會自動清除。核對後由使用者確認為實際持倉，或回到套用前。
- 快照標示實際持倉、待核對、試算或舊版未標記；還原試算會回到待核對狀態。資料由使用者填寫，工具沒有券商成交驗證。
- 情境比較兩條路徑都包含相同投入／提領，只有調整後扣除費用；顯示情境前後資產與價格變動損益。
- 快照按代號比對股數、價格、市值、現金與交割款。總資產差額不是投資報酬，投入／提領欄位也不是完整期間現金流。

### 驗證與發布狀態

`npm test` 同時驗證 V1、V2 與版本工具；`tests/v2_smoke.py` 測試匯入、合併寫入、離頁補存、容量不足、跨分頁衝突、成交核對、快照上限、手機版與暫用模式。`PORTAL_URL` 可指定含 `/433/` 的預覽根路徑，`CHROMIUM_PATH` 可指定 Chromium 執行檔。

CI 會執行上述瀏覽器流程並保存示範資料截圖。Pages 部署後會核對 `release.json` 的 commit 與每個版本的編譯網頁；入口及 V2 顯示建置識別。建置時間不是發布完成時間，是否上線以 Pages workflow 的部署及公開網址驗證結果為準。
